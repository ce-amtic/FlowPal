# 信息采集模块 设计文档

伴学计划 · 人大黑客松 Build with Care · 2026-09-04
状态：可开工。本模块与产品形态讨论解耦，形态怎么定都需要这一层。

---

## 1. 这个模块要做到什么

用一句话说：用户把任何东西扔进来，系统替他记住，并且理解成可以推理的结构。

产品其他部分（判断该做哪件事、缩小任务、画像）全部建立在这一层之上。这一层的质量决定了后面每一句话能不能具体到「你的那件事」。

设计原则：

1. **扔了就可以忘。** 用户扔完不需要做第二步。分类、填日期、归档都由系统做。
2. **三秒完成。** 任何一个入口，从想到「记一下」到完成，不超过三秒。
3. **每一条都可见、可改。** 系统的理解结果必须展示给用户，用户能一键修正。这是「扔了就可以忘」成立的前提。
4. **低打扰确认。** 只有系统不确定的时候才问用户，确定的直接入库。
5. **来源可追溯。** 每条结构化结果都保留原始碎片和引用位置，用户随时能看到「它是从哪句话理解出来的」。
6. **不做后台监控。** 不做 Recall 式的定时截屏。所有采集都由用户的一个动作触发，或由用户明确授权的数据源提供。

## 2. 采集入口

分三类：用户主动扔、系统级捷径、授权后自动同步。

### 2.1 手机端（信息来源）

| 入口 | 说明 | 优先级 |
|---|---|---|
| 系统分享菜单 | 微信、浏览器、邮件里长按 → 分享到本产品。这是手机端最重要的入口，覆盖绝大多数「看到一条通知」的场景 | P0 |
| 截图 / 拍照 | 群通知截图、课程公告、黑板、纸质材料。图片走 OCR + 视觉理解 | P0 |
| 文字 | 直接打字，一行输入框 | P0 |
| 语音 | 按住说话，转文字后走同一管道。适合走路、躺着时 | P1 |
| 剪贴板 | 打开应用时检测剪贴板有新内容，提示「要记这个吗」 | P1 |

手机端只负责扔，不负责看全貌。

### 2.2 电脑端（主要工作场景）

| 入口 | 说明 | 优先级 |
|---|---|---|
| 投放区 | 常驻的形象 / 窗口，文字、截图、文件拖进去即记录 | P0 |
| 全局快捷键 | 任意界面按快捷键弹出一行输入框，打字回车消失。专注中冒出杂念时用 | P0 |
| 粘贴 | 主界面任意位置 Ctrl+V，文本或图片 | P0 |
| 剪贴板监听 | 应用开着时，复制的内容在形象旁出现一张「未处理」的纸，用户点一下才入库，不点自动消失 | P1 |
| 文件拖入 | PDF、课件、通知文档。抽取其中的日期与事务 | P2 |

### 2.3 自动同步（用户授权）

| 数据源 | 接入方式 | 优先级 |
|---|---|---|
| 日历 | ICS 订阅链接 / CalDAV / Google Calendar | P1 |
| 邮件 | IMAP 拉取，只读最近 N 天，LLM 筛出含日期与任务的邮件 | P1 |
| 人大课表 | 教务系统导出 / 接口抓取，作为固定占用时间 | P1 |
| 人大校历 | 静态导入一次，提供「第 N 周」到具体日期的映射 | P0（推理依赖） |

校历标为 P0 的原因：校园通知里大量使用「第 8 周周三」「期中周」这类相对表达，没有校历就无法解析成日期。

### 2.4 明确不做

- Recall 式后台截屏：隐私风险、算力成本、演示时不可控。
- 微信消息自动抓取：技术脆弱，违反平台规则，演示需造数据。用分享菜单和截图替代。
- 强制要求用户选择类型或填表单。

## 3. 碎片类型

进入系统的所有东西先统一叫「碎片」。LLM 理解后归入以下五类，一个碎片可以产生多条结果。

| 类型 | 定义 | 例子 | 关键字段 |
|---|---|---|---|
| 事件 | 有确定时间点的外部节点 | 期中考试、换届、报名截止 | 日期、时间、地点 |
| 事务 | 需要用户做的事 | 交报告、准备组会 PPT | 截止日、预估量、关联事件 |
| 念头 | 专注中扔进来的零散想法，暂时不判断 | 「记得回小王」「查一下那篇论文」 | 原文 |
| 进度 | 某件事务做到哪了 | 「做到第三题，卡在积分」 | 关联事务、描述 |
| 状态 | 用户的自评或系统观察 | 「今天很累」、结束时的打分 | 精力、心情、时间戳 |

分类由系统做，用户看到的只是它理解后的一句话，不需要知道这套分类。

## 4. 处理管道

```
原始碎片（文本 / 图片 / 语音 / 文件 / 同步条目）
  ↓ 存档（原文永久保留）
预处理（OCR、语音转写、文件抽文本）
  ↓
LLM 理解
  ├ 抽取：类型、标题、日期、地点、关联对象
  ├ 日期解析：相对日期 → 绝对日期（依赖校历与当前日期）
  ├ 置信度：对每个字段给出高 / 中 / 低
  └ 引用：标出结论来自原文哪一段
  ↓
去重与合并（同一考试从群通知、邮件、课表多处出现）
  ↓
高置信度 → 直接入库
低置信度 → 进入待确认队列，主界面轻量提示
  ↓
入库，触发下游（时间轴更新、负载计数、推理）
```

### 4.1 LLM 抽取要点

- 输出严格 JSON，字段见第 5 节。
- 一条通知可能包含多个事件（「期中安排：高数 10.15，线代 10.17」），要拆开。
- 「本周」「下周三」「第 8 周」「考试周」必须结合当前日期和校历解析。解析不了的保留原文并标低置信度，让用户改。
- 对图片：先 OCR 得到文本，再交给 LLM；OCR 质量差时直接用视觉模型读图。
- 群聊截图会包含大量无关消息，让 LLM 只抽取含时间、任务、要求的部分，其余丢弃。
- 关联：新碎片要尝试挂到已有的事件或事务上（「补充一下，那个报告要 PDF 版」应关联到已有的「交报告」），而非新建一条。

### 4.2 去重与合并

同一件事从多个来源进来是常态。合并规则：

- 标题相似 + 日期相同或相近（±1 天）→ 视为同一条，来源列表追加。
- 日期不同但标题高度相似 → 视为「日期变更」，保留历史，标记为改期。改期本身是重要信号（画像里的「日期推移」）。
- 用户手动合并 / 拆分作为兜底。

### 4.3 确认策略

- 高置信度：入库，主界面上新增一条时轻微提示，不打断。
- 中置信度：入库，但在条目上标记「猜的」，用户看到可以点改。
- 低置信度：不入库，放待确认队列，主界面显示「有 2 条没看懂」。

用户永远可以不理待确认队列，产品不催。

## 5. 数据模型

```
Fragment（原始碎片）
  id, created_at, source（手机分享 / 截图 / 快捷键 / 邮件 / 日历 / 课表）
  raw_type（text / image / audio / file / structured）
  raw_content（原文、图片路径、转写文本）
  device

Item（理解后的条目）
  id, type（event / task / thought / progress / state）
  title
  date, date_confidence, date_raw（原始表达，如「第8周周三」）
  due_or_start（事务用截止，事件用开始）
  location
  related_item_ids（事务 → 事件；进度 → 事务）
  source_fragment_ids（可多个，合并后追加）
  citations（每个字段对应原文的哪一段）
  confidence（整体）
  status（active / done / dropped / needs_confirm）
  history（日期变更记录）

Calendar（校历与课表）
  term_start, week_map, fixed_slots（课程时间）
```

原则：Fragment 永不删除，Item 可以被用户改、合并、丢弃，但改动记录保留。

## 6. 用户看到的东西

采集模块对用户暴露的界面只有三处，UI 细节另行讨论，这里只定内容：

1. **投放入口**：一个可以扔东西的位置，扔完有一个接住的反馈，一秒内消失。
2. **条目列表**：每条一句话，写的是系统的理解，附来源标记。点开可以改字段、看原文、合并、丢弃。
3. **待确认**：单独一小块，只在有内容时出现。

## 7. 48 小时实施顺序

**第一批（今晚到周六上午）**
- 文本入口：主界面粘贴 + 全局快捷键
- LLM 抽取管道，JSON 输出，日期解析
- 校历静态数据
- 条目列表与编辑
- 数据存储（本地 SQLite 或 JSON 文件即可）

**第二批（周六）**
- 图片入口：截图粘贴 / 拖入，OCR
- 去重与合并
- 置信度与待确认队列
- 手机端：一个极简网页，文字 + 图片上传，同步到电脑端

**第三批（周六晚，有余力）**
- 剪贴板监听
- 日历 ICS 导入
- 语音入口
- 邮件 IMAP

演示所需的最小集合是第一批加图片入口。自动同步类如果做不完，演示时用「导入课表文件」代替，效果接近。

## 8. 演示数据

无论接入做到哪一步，都需要准备一套演示碎片，覆盖以下情况：

- 一张群聊截图，里面混着无关消息和一条期中考试通知
- 一封邮件文本，含报名截止日
- 一条口头风格的文字：「下周三之前把那个报告发给老师」
- 一条改期通知，和之前某条撞上，触发合并与「日期推移」
- 几条专注中扔进来的念头
- 一条进度记录

用这套数据能走完管道的每个分支。
