# Agent 与通用助手的边界是发起权，不是能力大小

用限制能力来保证「这不是通用聊天助手」是假的边界：工具给多给少，与产品是否同质化无关。真正的边界有三条，都不靠削减能力成立，且没有任何机制强制它们。

**一、主路径上产品先说话。** 用户不打字，东西也要在动。「此刻」是这条的具体化。通用 agent 的形态是「你不说话它不动」；首页正中一个大输入框，后面接再强的循环，看起来也与所有别的产品一样。

**二、模型每句话背后有一个指得出来的凭据**——逐字引文、库里的一条、一个工具结果。抽取的每个字段要引原文（[[007-extraction-contract]]），精力读数必须引一条给定事实（[[013-context-is-a-query]]），agent 不是唯一豁免的那一层。这条与能力大小无关：给它一百个工具，它照样成立。它是引用纪律的延续，不是防聊天的栅栏。

**三、真相在库里，不在对话里。** 用户触发的入口每次从库读，不带自己的会话历史。改一条不是「跟它说过」，是库变了，五个页面立刻都变。这条同时让「便宜模型够用」这个赌注成立——没有累积的上下文可以走丢。

为什么多数 2C AI 产品收敛成 Chat：GUI 必须把自己的能力画出来，能力边界模糊就画不出来，Chat 把「这东西能干嘛」的发现成本推给用户；GUI 是一份关于意图结构的承诺，Chat 让人永远不必做这个承诺；输出同理，不知道结果是什么形状时文字是万能容器。**Chat 是「还没决定」的形状**——通用性最大，贴合度为零。它们收敛过去不是因为品味差，是因为在模型之上确实没加东西，而对通用能力来说 Chat 是正确答案。

推论：出路不是避开 chat，是真把名词定出来。我们定了五类条目、项目、处境，所以直接操作在能指着的地方胜过语言。**语言的价值只在于指称指不着的东西**——这也是为什么改期、标完成、改归属的正确形态是 `/items/:id` 上的字段，而不是一个语言入口。写入口的存在理由见 [[016-agent-loop-single-write-mechanism]]，它的输入是碎片，不是 prompt。
