# 进待确认的门槛是「错了不可逆」，不是「模型没把握」

待确认队列不是模型的免责通道。一条判断进不进待确认，看的是**错了的代价**，不是模型的信心：

- **合并两条 → 进。** 合错了两件事永久并成一件，用户拆不回来。
- **低置信度的抽取结果 → 进。** 烂数据落进库会污染后面每一次判断。
- **项目归属 → 不进。** 归错点一下就改过来了。

反过来同样成立：模型没把握但错了无所谓的，直接落库并标出来，不要拦住用户。默认是让系统自己走完，用户零介入；需要介入的地方越少，「扔了就可以忘」才成立。

违反这条的表现是把所有拿不准的东西都塞进待确认，于是队列变成一道必答题，产品从「替你记住」退化成「让你填表」。这与 [[001-fragment-immutable-item-derived-with-citations]] 的低打扰确认原则是同一件事的两个说法。
