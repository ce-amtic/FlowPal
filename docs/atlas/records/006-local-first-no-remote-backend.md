# 唯一真相是笔记本上的进程，手机端局域网直连，不做远程后端

数据的唯一真相是笔记本上那个 Node 进程（Electron 主进程内的 HTTP server + SQLite）。手机端如果做，就在同一局域网内 POST 给它，只写不改，因此不需要写任何同步逻辑。这 (answers:: [[004-multi-device-sync-open]])。

不做远程后端的理由有三条。硬约束要求 demo 现场本地可运行、不依赖线上部署，上云意味着会场网一断整个演示死掉，而不只是手机那一段。真正贵的不是服务器而是同步语义：碎片是 append-only 的好办，但条目可改、可合并、可丢弃，两端同时改就要处理冲突、离线队列与版本，这是 CRDT 味道的问题，剩下的时间里碰它是陷阱。以及演示本身不需要双向同步——手机只负责扔。

这个选择不关门：因为接口是 HTTP，server 跑在哪台机器上只是 base URL 的区别，将来上云是同一份路由换台机器跑。反过来若选了 IPC，逻辑就长死在 Electron 主进程里。

配套的一条约束：server 默认绑 127.0.0.1，局域网监听是显式开关，打开才绑 0.0.0.0 并要求 token（启动时生成随机串，界面出二维码编码地址加 token，手机扫码配对）。已识别的失败模式是黑客松公共 wifi 上挂着一个无鉴权、能写库、能烧模型额度的接口。扫码顺带解决了「手机怎么知道笔记本 IP」，鉴权是搭车来的。

已知残余风险：会场 wifi 常开 AP 隔离，手机连不上笔记本。兜底是两台设备连同一个热点；手机本来就不在演示关键路径上。
