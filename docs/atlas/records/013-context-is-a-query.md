# 处境是一个查询，不是一份画像存储；精力给事实不给数

「处境」是语义层的一个纯函数 `buildContext(ctx)`，不是一张表、不是自然语言画像文档、不是向量库。

排掉的两条路：**画像文档**会漂、会编，一旦重写就丢了来源，用户没法问「你凭什么这么说」，直接违反 [[001-fragment-immutable-item-derived-with-citations]] 定的可追溯原则；**向量检索**在几百条条目的量级上是纯负担。

判断一条事实是否属于处境的尺子：**它会改变产品说什么、挑哪一件，才算。** 拿掉它输出不变，它就是装饰。

输出按**来源**分四节，每节标明来源，prompt 据此知道哪些能断言、哪些必须留余地。来源标签替代了画像文档该干的活：

1. **算出来的**——离截止多久、并行几件、被改期几次（`item_history` 带 `fragment_id`）、某项目多久没动。
2. **观察到的**——只用专注时段无条件产生的四个数：开始时刻、计划时长、实际时长、是否提前结束。
3. **用户说的**——存成「状态」条目，可见可删。不主动问。
4. **先验**——必须标明是猜的。

**只用行为本身必然产生的信号。** 「这段里扔了几条想法」一类被明确排除：它依赖用户是否使用某个可选功能，缺席时是歧义的（没杂念，和没用这个功能，是同一个空值），在歧义的空值上做推断得到的是噪声。

**精力不建模成一个值。** 任何数值（0.63 也好、三档也好）都是从几条事实里挤出来的，挤的过程只丢信息：模型看到 0.63 不知道它从哪来，且每次调用的理解不一致。改为直接给事实——起床与入睡时刻、chronotype、今天的课密度、此刻距起床多久、今天已有的专注——由模型判断。模型对这些有真实的世界知识，而可解释性变成免费的。

曲线四层来源，只有第四层需要历史数据：文献里的先验形状；MCTQ 短式两问算出的 chronotype（首次启动问一次）；**当日课表**（最强的一层，第一天就有、完全个人化、可解释）；专注记录的观察修正（数据不足时不参与计算）。

模型输出里 `energy_reading` 字段放它的判断，**必须引用至少一条给它的事实**，与引用逐字可验同一套纪律。

明确排除：情绪与性格标签（推不出来，写出来是模型下评语，与 [[002-llm-tone-present-not-judging]] 冲突）；屏幕与 App 使用记录（非目标）。

代价说明：到冻结时库里只有几小时数据，演示里任何「长期」的话来源是预置数据或先验。这条路的价值恰在于此——模型只能说出行里有的东西，说不出趋势时它就说不出，不会编一个。
