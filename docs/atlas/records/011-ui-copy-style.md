# 界面文案：正式、清晰、简明，不写面向开发过程的元语句

界面上所有面向最终用户的文字——包括模型生成的那部分——使用正式、清晰、简明的语言：

- 不口语化。
- 不自创听不懂的黑话。
- 不啰嗦、不用赘语；能用一个词或一句话说清的，绝不用一段话反复讲。
- 不写解释性的元语句（面向开发过程的说明、对功能自身的介绍、"这里将会…"一类）。
- 同一语义的元素或操作以同一形态、同一措辞出现，除非它们确有不同。语义不同就换词：「换一件」是另一件事，「更小的一步」是同一件事更小的切口。

这条约束要写进抽取与「此刻」的 prompt，不只约束手写文案。它与 [[002-llm-tone-present-not-judging]] 是两条不同的规则：那条管态度（在场而不评判、不责备不催），这条管措辞。
