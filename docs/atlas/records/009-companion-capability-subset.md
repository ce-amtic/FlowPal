# 桌宠与主窗口分量相等：能力是子集，交互形式可独有

桌面上常驻的形象与主窗口是两个分量相等的表面，关系由一条规矩固定：**桌宠的能力是 App 能力的子集，但交互形式可以是它独有的。**

- 没有任何能力只存在于桌宠。它能做的每件事，主窗口里都有一个不着急的等价版本；桌宠不启动，App 功能完整。
- 交互形式可以独有。把桌宠抱起来拖到某个窗口上完成一次采集，是只有这个形态做得出的动作。
- 它不主动猜用户在干什么。气泡只出现在两种时候：用户刚对它做了一个动作（回执），或到了用户自己设定过的时刻。
- 它说的每句判断旁边都有一个否定入口。

理由是两类已知失败：Microsoft Bob 的病根是角色成了必经之路（想开文件得先跟角色对话）；Clippy 的病根是主动打断且不可反驳。前者由第一条规避，后者由第三、四条规避。

代价是每个功能要做两遍——桌宠一份急的，主窗口一份全的。接受这个成本，因为省掉的恰恰是会被当场戳穿的那一份。
