# 专注结束的两个按钮是关于那件事，不是关于这段时间

一次专注结束时只有「已完成 ｜ 下次继续」两个按钮，零打字。它们指向的是那件事的
去向，不是对刚过去这段时间的评价——评价会把结束变成一次自陈，而自陈在「刚结束、
想赶紧关掉界面」的那一刻质量最差（[[014-no-progress-tracking]]）。

- **已完成** 把条目记成完成，「此刻」从此不再推它。**只对事务生效**：事件是外部的
  时间点，为一场考试专注过一段不等于那场考试结束了，把它记成完成会让它从日程上
  消失——而那恰恰是最该留着的一条。
- **下次继续** 不改条目，只把这一段记成没做完，并让下一次「此刻」把它排到前面。

「下次继续」能改变下一次「此刻」，靠的是两件互相独立、缺一即失效的事：

1. 处境里那条专注记录**必须带事情的名字**。原先只写「今天 14:20 开始，计划 25
   分钟，实际 12 分钟，提前结束」，模型接不上一件它叫不出名字的事。
2. 写入时**必须清掉「此刻」的缓存**。否则前端刷新拿回来的仍是上一次的判断。

补上这两处之后实测：对一件条目按「下次继续」，下一次「此刻」把它选为主推，理由是
「距离截止只有两天，且今天已经开始过，最容易接着做」——「接着上次」是模型从事实里
自己读出来的，没有为它写任何提示词。

由此得出一条更一般的：**处境里的每条事实都要能指回一个有名字的对象**
（[[013-context-is-a-query]]）。一条只有数字和时间的事实，模型能读懂但用不上，
因为它无法把这条事实和清单里的哪一行对上。
