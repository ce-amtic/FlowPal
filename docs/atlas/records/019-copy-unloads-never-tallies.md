# 面向用户的话要卸载，不要清点

写给用户的任何一句话——尤其模型生成的——读完之后他手上的事必须变少，不能变多。

同一个事实两种写法效果相反：「未来 7 天有 9 件事到期，跨 5 个项目」是把压力原样
还回去；「明天傍晚要用的只有这一件，其余八件都还有时间」压力就降了。焦虑主要来自
高估「要求」，产品的作用是把这团东西拆开、把不急的挪走。

两条具体禁令：

- **不复述统计。** 件数、项目数、专注次数一律不出现在句子里。有凭据不等于把凭据
  念出来——概括它。
- **不写用户活动的零计数或负向计数。**「今天已完成 0 次专注」形式上是事实，读起来
  是「你什么都没干」，是羞耻驱动的教科书写法。

回避型情境（项目久未动、反复改期）同理：这些信号可以用来**选**该做哪件事，但不能
出现在句子里。看见的方式是挑中它，不是说出来。
