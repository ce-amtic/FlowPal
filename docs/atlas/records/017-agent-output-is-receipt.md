# Agent 的输出是回执不是结果；进行中播对象，不播步骤

一次循环要呈现三个时刻：接住了、在做、做完了。全部由桌面上的形象承担，形态见 [[009-companion-capability-subset]]。

**气泡里那句话是回执，不是结果。** 结果是库变了，库变了五个页面跟着变。气泡负责的只是「接住了、做了什么、要看的话在哪」。

气泡两行：模型那句话，其下一行动作痕迹（`新建 3 条 · 更新 1 条`），可点，点开主窗口跳到「最近」并高亮这一批；有 `needs_confirm` 的，该行换成 `1 条待确认`，点击直达该条。**不做消息流，不留历史**，数秒后自行收回。历史在「最近」页——它是 agent 全部动作的落点，这也是那一页的定义。

**进行中播对象，不播步骤。** 循环跑三步还是八步用户不需要知道，工具名更不能逐条播出——那是面向开发过程的元语句，与 [[011-ui-copy-style]] 冲突。呈现的是「在看这张截图」「在对照机器学习这门课」「在找和面试有关的条目」。

**这几句不由模型生成**，由工具调用的参数在前端本地映射（`getProject(id=3)` → 「在对照机器学习」）。模型因此没有机会编造一句好听但不真的意图，也不增加它的负担。附带效果是「它去查了项目背景」这件事被看见，而那正是这个产品该被看见的部分。

进行中状态走第二条 SSE，`GET /api/runs/:id/events`，**携带工具名与参数但不携带工具结果**。这不违反「跨窗口事件不携带内容」：那一条管的是实体变更，实体在库里另有真相；一次循环的进行过程是瞬时的，库里没有它，除了这条流没有别的来源。推工具结果则会把碎片原文送进渲染进程，而气泡用不到。

**主动说话用同一形状，但时机受限**：只在明确事件上——专注结束、同步带来一条外部改期。**不定时冒泡**，那会滑向催促。产品先说话的主场是「此刻」页，不是气泡。
