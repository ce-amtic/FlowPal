# Now page redesign

Continues `docs/atlas/design/2026-09-05-product-form-and-main-window.md`.

上一轮定了五页的分工与「此刻」装什么。这一轮解决三件缠在一起的事：形象进来之后
这一页是什么、agent 的输入口在哪、以及模型写出来的那几句话为什么没人想读。

## Decided

### 形象

- **主窗口里它是装饰，不承担任何功能入口。** 表情固定 calm，不随系统状态变。
  判据：把它整块删掉，应用的每个动作仍然做得到。这是 Microsoft Bob 那一课的
  可执行形式——任何功能都不能只有经过它才能到达。
- **活的，但只保留眨眼与跟随视线。** 完全不动的形象在桌面上像贴纸；这两样是
  「不突兀」与那点温度的来源。
- **尺寸 128，左上角**，问候语与精力那两行在它右侧。96 在 620 宽的正文列里太小，
  160 开始和「一件事」那张卡片抢。
- **照着 `docs/quiet-pebble.html` 在 `packages/app` 里重写一个精简版，参考件本身
  不动。** 只保留形体、表情、眨眼、跟随视线；去掉拖拽抱起、轻弹、转身，以及
  颜色 / 尺寸 / 柔软度那套调参控件——那些属于桌宠窗口与原型页。
  - 必须改的两处：参考件把背景色 `#eff0ed` 写死在 fragment shader 里，且 WebGL
    上下文是 `alpha:false`，原样嵌入会盖掉页面底色与 Electron 毛玻璃；接触阴影
    也画在那块底上，要改走 alpha 输出。
  - 组件接口按 `pet.setExpression(name)` 那一套设计，桌宠窗口拿去装进另一个容器
    时不用改内部——「桌宠的能力是 App 的子集」在代码层面就是同一个组件、两个容器。
  - 判据：开系统「减弱动态」后不动；窗口隐藏后 rAF 停。前者的出处是既定的
    「三档时长一起归零、不留例外」，后者是常驻 WebGL 的实际代价。
- 桌宠窗口归桌面侧，与这一处并行做，冗余之后再清理。

### 页面结构

四块，自上而下：**形象＋问候＋精力 / 卡片 / 记录框 / 接下来**。

- **记录框并入「此刻」，固定在窗口底部**，内容在它上方滚动；库里没有可推的东西时
  它上移到形象下面。只在「此刻」出现——每页都挂等于给整个应用加一条底栏，而其余
  四页是查看的地方。标题栏的加号改为回「此刻」。
  - 形态：上一行文本框，下一行动作。
  - 回执原地一行、不堆积、几秒后消失。堆积就成了对话流，而「此刻」的正文永远是
    那一件事，不是你和它说过的话。
- **卡片补上事情的名字**，小字，在大字步骤上方，并且这行名字就是通往条目详情的
  链接。接口早就返回了 `title`，界面没渲染，于是卡片上只有一个孤立的步骤——
  「出处」看不懂的根因在此，不在那个词。
- **「出处」控件删除，`basis` 这一页不渲染。** 它返回的是一串裸 id，且与
  「为什么是它」之间没有逐字关系可验，摆出来是噪音。prompt 里那条要求保留：
  逼模型点名用了哪些材料，这个约束本身在改善输出，只是不给用户看。
- **「重新判断」移到页面右上角，改为图标，标签叫「刷新」。** 它是页级动作，不是
  这张卡片的动作；留在动作行里，会让一个要花几秒和一次模型调用的东西混在三个
  零延迟的本地切换中间。
- **「接下来」按未来 7 天列，超出就滚**，更远的收成一行「还有 N 件」通向日程。
  7 天不是拍的：`buildContext` 算的就是这个窗口，模型判断用的也是它，界面与判断
  用同一个窗口，用户看到的「剩下的」就是模型看到的「剩下的」。这条同时划清了它
  与「日程」的分界（7 天的安心凭据 vs 14 天的完整轴）。
- 问候语保留。它是全页唯一一句没有凭据的话，按用户偏好留着，为的是那点温度——
  记为偏好，不是原则。
- 判据：三种数据形态各截一次图，浅色深色各一遍——空库、一件事、多候选。人看，
  没有自动化替代，承认这一点。另加一条：`NowPick` 的四个字段全部落到界面上，
  既没有渲染不出来的字段，也没有界面上凭空多出来的话。

### 文案

模型写出来的话难看不是发挥失常，是 `prompts/now.md` 直接导致的。两处根因：
`reason` 那条列了四个维度，模型就把四个从句串成一句；`energy_reading` 要求
「必须至少引用一条输入里的事实」，于是精力那句变成统计复述，而且和 `reason`
抄的是同一条。

**最关键的一条：要卸载，不要清点。** 焦虑主要来自高估「要求」。同一个事实两种
写法效果相反——「未来 7 天有 9 件事到期，跨 5 个项目」是把压力还回去；「明天傍晚
要用的只有这一件，其余八件都还有时间」压力就降了。自检：读完之后他手上的事是变多
还是变少。

从外部范文里提炼出的规则（范文见下方 Keepers）：

1. **每一步是一个能做完、有终点的物理动作。** 禁止「看一眼」「了解一下」
   「熟悉一下」这类没有终点的说法。
2. **不许用「只」「不用」跟用户讨价还价。**「只打开模板」「只读那一段，不改」——
   直接给一个小动作，不还价。
3. **三级步骤逐级变小**，每级都是完整的一句，不加限定语。
4. **精力那句概括处境，不复述数字。** 有凭据不等于把凭据念出来。禁止出现件数、
   项目数、专注次数。这一条推翻了原 prompt 的「必须至少引用一条事实」。
5. **精力与「为什么」不再硬分工**，只禁止两句抢同一条事实。原来规定精力不许说
   该做什么，堵错了地方。
6. **回避型情境不说破。** 项目久未动、反复改期、今天还没开始——可以用来选，不能
   出现在句子里。看见的方式是挑中它，不是说出来。
7. 数字写中文（「十天」不写「10 天」）；用「可以」不用祈使句；一句话一件事，
   最多两个逗号，不用分号；不出现 ISO 时间戳。
8. 「为什么」只给一个理由，最强的那个。
9. 用户自己说过的话是最强的材料，有就优先引用，原样引用。
10. 原有的不评价、不催、不责备、不谈意志力继续有效，另加一条：**不写用户活动的
    零计数或负向计数**——「今天已完成 0 次专注」形式上是事实，读起来是指责。

- **只把「一直在躲」那一组范文作为 few-shot 放进 prompt**，另外两种情境规则说得清。
  三组都放，模型会连「组会」「简历」这些具体内容一起抄。
- 判据：界面上不出现裸 id、不出现面向开发的元语句。加一条扫描，查 `itm_` / `prj_`
  前缀有没有出现在 JSX 文本里——`basis` 那串裸 id 差点直接渲染出去，这类错误肉眼
  容易漏。其余靠人读。

### Keepers

- `docs/文案需求-此刻.md`：给外部写文案的人的需求书。它记录了三种情境的真实数据
  与硬规则，prompt 之后每次改都要对着它验，所以留着。
- 外部范文三组（下），是上述规则的来源，规则读不明白时回来看它们：

  **压得满** — 精力：这几天事情比较集中，可以先安排眼前的一件。／一步：写下组会要
  讲的一个要点｜新建文档，写上组会标题｜打开一个空白文档／为什么：组会材料明天傍晚
  要用，是目前截止时间最近的一件。

  **很空** — 精力：目前只有一项报名，时间还比较宽裕。／一步：查看报名需要哪些材料｜
  找到科研项目的报名通知｜搜索科研项目的名称／为什么：距离报名截止还有十天，可以先
  了解要求，再安排准备时间。

  **一直在躲** — 精力：最近的截止在六天后，今晚可以留一点时间给简历。／一步：标出
  简历里可以删减的一处｜打开简历，读其中一段｜打开上次那版简历／为什么：你上次提到
  简历两页压不住。先找一处可以删减的内容。

### Throwaways

- 「这一页不该需要滚动」——提出时没有出处，用来给「接下来」定长度是错的。真正的
  约束是卡片必须在首屏之上，首屏以下滚不滚与它无关。
- 把 `basis` 做成凭据条或连到「接下来」高亮的两个方案，都随「不渲染」一起作废。
- 形象按系统状态换表情（curious 正在理解 / happy 落库成功 / sleepy 深夜）——
  定成装饰之后不做。

## Still open

- **待确认的门槛被实现绕过去了。** `store/items.ts` 里 `confidence === 'low'` 就落
  `needs_confirm`，而既定的门槛是「错了不可逆」，不是「模型没把握」。现场三条待确认
  里有两条是这么进去的，角标常年挂数字，正好变成我们要避开的那种催人清空的收件箱。
  `prompts/agent.md` 第 7 条也写着「低置信度会进待确认」，两处要一起改。这一轮没解。
- **「专注」该不该是独立一页**，用户明确搁置。
- 外部范文只覆盖了三种情境。**同一件事被连续换掉多次、以及库里全是没有日期的事**
  这两种，语气还没有校准过。
- 记录框固定底部之后，**滚动区与它的交界怎么处理**（内容滚到底时是否被遮住一行）
  没有验证过，要看实现出来的样子。
